# 🐜 懶螞蟻公司模擬器 使用說明書

## 1. 這是什麼？

這是一個「組織韌性」模擬器。它想回答一個問題：

> 公司裡那些看起來在摸魚、**遇到大事才出手**的人（高反應門檻員工），是浪費薪水，還是公司撐過突發大急單的保險？

模擬方式是：100 隻「糰子」（員工）、模擬 520 週（10 年）、每週有工單湧入，偶爾遇到大急單。工單堆太多公司就倒閉。比較 6 種管理策略，看哪種公司活得久、產出多。

- **3D 互動模式**：看糰子上班、休息、過勞倒下。
- **蒙地卡羅模式**：同一組設定跑 1,000 次，統計「10 年存活率」。

## 2. 安裝與啟動

需要 Node.js 18 以上。

```bash
cd lazy-ant-company
npm install          # 安裝相依套件（有 lock 檔可用 npm ci）
npm run dev          # 啟動 3D 互動介面，依畫面提示開啟網址（通常是 http://localhost:5173）
```

其他指令：

| 指令 | 用途 |
|---|---|
| `npm run mc` | 命令列蒙地卡羅：6 組 × 1000 次 + 參數掃描，約 13 秒 |
| `npm run mc -- --runs=200 --seed=7 --sweep=false` | 自訂次數、種子，並略過掃描 |
| `npm test` | 單元測試與定性校準測試 |
| `npm run test:targets` | 檢查 SPEC §5 的數值目標（目前 3/5 未過，屬已知現況） |
| `npm run build` | 型別檢查並建置正式版（輸出到 `dist/`） |
| `npm run preview` | 預覽建置後的成品 |

## 3. 角色（糰子的顏色）

| 顏色 | 名稱 | 反應門檻 | 行為 |
|---|---|---|---|
| 🔵 藍 | 勤勞 | 0–10 | 只要有一點工作就出勤 |
| 🟡 黃 | 高門檻（備用人力） | 22–34 | 平常在茶水間休息，待辦量高到門檻才出手 |
| 🟣 紫 | 真擺爛 | 永不出勤 | 危機也不動 |

「門檻」的意思：當剩餘待辦量大於等於自己的門檻，才會去工作。

## 4. 3D 介面操作

### 畫面配置
- **辦公區（左）**：10×10 格，工作中的糰子會彈跳。
- **茶水間（右上，綠地板）**：休息回體力。
- **過勞休養區（右下，灰地板）**：體力歸零的糰子倒下並閃紅光，要休養 2 週。
- **中央柱子**：待辦工單堆。**紅色環**是倒閉紅線，待辦超過救火警戒線時會閃紅燈。
- **頭頂細條**：該糰子的體力。

### 上方控制列
| 控制項 | 說明 |
|---|---|
| 單視圖／雙視圖對照 | 雙視圖會把兩個策略並排比較 |
| 實驗組（A / B） | 選擇策略，見下一節 |
| Seed | 隨機種子。**相同種子下，不同策略遇到的工單與大急單時間完全一樣**，所以比較公平。改種子或策略會自動從第 0 週重來 |
| ▶ 播放／⏸ 暫停 | 開始或暫停時間 |
| ⏭ 單週 | 前進一週 |
| 1x / 5x / 20x | 播放速度 |
| ⚡ 跳到下次大急單 | 跳到下一次急單開始前一週 |
| ↺ 重來 | 回到第 0 週 |
| 右側時間顯示 | 第幾週／總週數，以及換算成幾年 |

某組倒閉後，該畫面會停在倒閉那一週。

### 右側蒙地卡羅面板
1. 按 **🎲 跑 1,000 次蒙地卡羅**，在背景執行，不會卡住畫面。
2. **10 年存活率長條圖**：6 種策略各自活到第 520 週的比例。滑鼠移上去可看平均十年產出。
3. **備用人力比例曲線**：固定 100 人，黃色比例從 0% 掃到 60%，看存活率變化。理想上會呈現「倒 U 型」，在 20–30% 附近最高。
4. 使用的是目前設定的 Seed。

## 5. 六種管理策略

| 策略 | 組成 | 特色 |
|---|---|---|
| 原版公司（28 法則） | 80 藍 + 20 黃 | 標準規則，有茶水間 |
| 開除摸魚組 | 80 藍 | 把 20 隻黃的開除 |
| 全員捲王 | 100 藍 | 沒有茶水間，人人每週強制滿載 |
| 真擺爛公司 | 80 藍 + 20 紫 | 備用人力是真的不做事 |
| 裝監控盯梢 | 80 藍 + 20 黃 | 禁止進茶水間，沒事也得假忙，假忙會扣體力 |
| 留餘裕＋救火獎金 | 80 藍 + 20 黃 | 平時放心休息，紅燈時救火隊出動，效率 1.25 倍 |

預期結論（定性排序）：**留餘裕＋救火獎金 > 原版 ≫ 全員捲王 ≈ 裝監控 ≫ 開除摸魚 ≈ 真擺爛**。

## 6. 模擬規則（每週流程）

1. **工單湧入**：每週約 50 件新工單；若處於大急單，額外增加。大急單每週約有 2.9% 機率觸發，持續 3 週。
2. **過勞恢復**：過勞者倒數，滿 2 週後回到休息狀態、體力 45。
3. **出勤判定**：依門檻由低到高，決定誰來上班。
4. **產出結算**：每位上班者每週處理約 0.75 件工單（救火時 0.94）。
5. **體力結算**：上班扣體力；休息回體力；體力歸零就過勞。
6. **倒閉判定**：當週結算後待辦量超過上限就倒閉，模擬結束。

數值（體力消耗、恢復量、倒閉線等）可在 `src/sim/config.ts` 的 `DEFAULT_PARAMS` 調整。

## 7. 已知限制

- 原始規格遺漏了常態工單的分佈公式，實作採用 N(50.5, 6²) 並校準。
- 為了讓「倒 U 型」出現，加入了 `allocationPerWorker` 這個詮釋參數（大家看到工作堆會一窩蜂湧上去、互相重疊）。
- 數值目標有 3 項未達標：原版與救火組的絕對存活率偏低約 10 個百分點，倒 U 兩端落差約 9–10 個百分點。排序與趨勢都成立。
- 詳細校準結果與詮釋見 `README.md`，完整原始規格見 `SPEC.md`。
